## 4.1 什么是模型？

模型：就是人工智能这个学科最重要的产物。人工智能学科就是用模型这个产物，来模拟人类的大脑。

注意：模型的本质其实是通过数学计算来模拟人类的思维、完成特定的功能或结果。它并非完全复现人类的思维（涉及意识、情感、直觉等尚未被数学化的领域）。

Google DeepMind 的研究员 Alexander Lerchner 在其论文《抽象谬误The Abstraction Fallacy》中有一个很形象的比喻：Simulating rain, no matter how realistic, will never wet the circuit board; similarly, simulating consciousness, no matter how realistic, will never produce subjective experience.

翻译：计算机模拟降雨，无论模拟得多么逼真，也不会弄湿电路板；同理，模拟意识，无论模拟得多么逼真，也不会产生主观体验。

### 4.1.1 大语言模型

最初的模型参数量比较小，显得比较智障。但是当参数量达到一定级别之后，业内普遍认为是数百亿到数千亿之间，出现了智能涌现，让模型越来越聪明，这跟我们人类的智能是一样的，大脑里面单个的神经元无法产生智能，当无数个神经元组合在一起，我们人类也突然有了智慧，这都是涌现的体现。

为了跟以前参数量比较小的模型加以区分，参数量比较大的模型，我们叫做大模型。

而最初的大模型只能处理文本数据，所以我们也把这类只能处理文本数据的大模型称之为大语言模型（Large Language Model），简称：LLM。

### 4.1.2 推理大模型

大语言模型（如GPT系列）虽然在文本生成、对话等任务上表现出色，但其核心能力仍局限于“直进直出”概率驱动的文本预测，他是预测下一字，而不是真正的理解了文字之间的逻辑，这导致以下问题：

- 复杂任务表现不足：在数学、科学问题求解等需要多步分解的任务中，传统语言模型易出现逻辑断裂或"幻觉"。
- 缺乏反思能力：模型无法像人类一样通过"慢思考"验证中间步骤，导致错误累积

举例：

1. 老版本的大模型：几乎所有的大模型在回答9.11跟9.9谁更大，几乎都说错了。简单来说，他是背上了数学书，但是并没有理解数字之间的联系，只不过这个问题现在已被解决。

2. 复杂逻辑问题，目前部分AI还是没有回答正确，比如：洗车问题。

- 上下文理解能力：推理大模型能够更准确地理解文本中的上下文信息，把握整体语境，从而做出更为精准的判断和推理。
- 复杂关系推理能力：擅长处理需要多步骤逻辑推导的复杂任务，如解谜、高级数学问题、复杂的编码任务等。
- 链式思维：在回答问题之前，推理大模型会生成一系列中间推理步骤，逐步推导出最终答案，这种链式思维使得其答案更具逻辑性和说服力。

所以，现在新推出的大模型，大多都具备推理功能，可以处理复杂的内容。

### 4.1.3 多模态大模型/全模态大模型

大模型能处理的一种类型的数据叫做一个模态，比如文本就是一种类型的数据。但是仅仅只能处理文本还不够，我们还想让大模型能处理其他类型的数据，比如：音频，图片，视频等。

多模态大模型：能处理两种及以上类型的数据。

全模态大模型：能处理所有类型的数据。

目前主流的大模型已经基本全面转向多模态/全模态。纯文本模型正在快速成为"过去式"。

所以在以后，如果我们要利用AI生成前端页面，如果选择只能处理文本的大模型，只能通过文字描述。但是如果使用多模态大模型，就可以直接给他一张图片，按照图片生成页面，非常的方便。

课堂提问：

DeepSeek是大语言模型，还是多模态大模型？

回答：只能处理文本的大语言模型。

理由：Deepseek在处理图片的时候，获取的是图片上的文字，从本质来讲，还是只能处理文本，并不像其他模型一样可以看懂图片，并且生成图片，只不过DeepSeek在处理文本这个领域当中全球领先。

### 4.3.1 token词元

大模型的计费规则只有一种，就是我们现在要了解的token。

token（词元）：词元就是词语的组成单元。

- 中文语境：可能是一个字，可能是一个词语，也有可能是一个偏旁部首。
- 英文语境：可能是一个单词，可能是多个单词，也有可能是单词的一部分。

这跟大模型训练的数据有关，大模型会把经常出现的部分当做一个词元，不同大模型的的规则有可能是不一样的。

举例：我叫张三，身高1.7m，体重70kg，爱好游泳。

DeepSeek：我叫丨张三丨，丨身高丨1丨.丨7丨m丨，丨体重丨70丨kg丨，丨爱好丨游泳丨。

豆包大模型：我丨叫丨张三丨，丨身高丨1丨.丨7丨m丨，丨体重丨7丨0丨kg丨，丨爱好丨游泳丨。

## 4.4 环境搭建（续 3）

- 用户变量：仅对当前登录的该用户有效。使用其他的用户账号登录这台计算机时，无法使用这些变量。
- 系统变量：对所有的用户有效，无论哪个用户登录，都可以访问到这些变量。

可以在系统变量找到环境变量 - Path

> Path环境变量：操作系统运行一个程序或命令必须先找到对应的程序，然后才可以执行。 而在查找程序的时候，默认会在当前路径寻找，如果当前路径未找到，则会去Path环境变量指定的路径中查找。【如果我们想在任何的路径中，都可以执行某一个程序，就可以将其配置在Path环境变量中】

我们可以来看一下，在我们装好了Python之后，正常情况下，其实已经自动帮我们配置好了环境变量了，因此呢，现在在任意的目录下，我们都是可以执行python命令的。

如果显示python不是内部或外部命令，证明安装时自动配置出问题了，我们只要把下面两个命令配置到Path当中即可

E:\devlop\python

E:\devlop\python\Scripts

环境配置：

1. 新建文件夹待用

> 注：如果安装的时候，没有修改路径，默认安装到C盘，本步骤跳过

在..\develop\node\文件夹里面新建两个文件夹node_global和node_cache，解释：

- node_global：利用nodejs下载的所有工具
- node_cache：下载时候的缓存内容
2. 修改nodejs的配置信息

> 注：如果安装的时候，没有修改路径，默认安装到C盘，此处只要修改registry镜像地址，无需修改prefix和cache

- 把npm后续下载的工具，移动到node_global文件夹中，不占用C盘空间

安装win---> 搜索cmd ---> 选择以管理员身份打开cmd ---> 输入以下指令

```apache
npm config set prefix "node_global路径" // 注：这里的路径是node_global文件夹的完整路径
举例：
npm config set prefix "E:\develop\node\node_global"
```

- 把npm下载时的缓存文件，移动到node_cache文件夹中，不占用C盘空间

```apache
npm config set cache "node_cache路径"  // 注：这里的路径是node_cache文件夹的完整路径
举例：
npm config set cache "E:\develop\node\node_cache"
```

- 修改nodejs默认镜像下载地址，变成国内的

```apache
npm config set registry https://registry.npmmirror.com
```

4. 修改环境变量(一般node安装完毕就已经配好, 直接输入命令验证,, 如果失败了, 需要手动配置, 不是必须的!!!!!!!!!!!)

> 注：如果安装的时候，没有修改路径，默认安装到C盘，本步骤跳过

打开用户变量，注意是用户变量，不是系统变量

把用户变量里面path中最后一个修改第一步新建`node_global`文件夹的路径

5. 确认node安装成功

打开cmd输入命令：

```apache
node --version  // 显示版本号：v24.15.0
npm --version // 显示版本号：11.12.1
```

> 备注：成功显示版本号代表安装成功，nodejs的版本号必须大于等于v18.0.0，npm版本号必须大于等于8.19.4
