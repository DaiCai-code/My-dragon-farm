## 1.1 claudecode的权限控制

### 1.1.1 配置文件方式

为了减少点击yes的频率，我们可以给claudecode放开一定的权限，比如：读写文件等。

配置方式如下：

- 打开Claude Code 的全局配置文件，位于 `~/.claude/settings.json`

{
"env": {
"ANTHROPIC_BASE_URL": "大模型的的BASE_URL",
"ANTHROPIC_AUTH_TOKEN": "自己的APIKEey",
"API_TIMEOUT_MS": "3000000",
"CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1",
"ANTHROPIC_MODEL": "大模型的名字",
"ANTHROPIC_DEFAULT_SONNET_MODEL": "大模型的名字",
"ANTHROPIC_DEFAULT_OPUS_MODEL": "大模型的名字",
"ANTHROPIC_DEFAULT_HAIKU_MODEL": "大模型的名字"
}, // 注意这里要加个逗号，跟昨天的模型配置加以区分
"permissions": {  // 给claudecode添加的权限
"allow": [ // 允许的权限
"Read",  // 读取文件中的内容
"Write", // 写入文件
"Bash(npm *)", // npm命令
"Bash(git *)", // git命令
"Bash(node *)" // node命令
],
"deny": [ // 禁止的权限
"Bash(rm -rf *)"  // 全局删除
]
},
"autoCompactThreshold": 80 // 上下文达到80%的时候自动压缩
}

配置完毕之后，重启claudecode，可以再次询问：

### 1.1.2 快捷键方式

在claudecode中，还可以通过快捷键控制权限，可以让他一次性生成结束，不需要我们反复点击YES，但是该方案风险较高。

快捷键：Shift + Tab

| 权限 | 说明 |
| --- | --- |
| plan mode on | 计划模式 |
| manual mode on（手控方式） | 所有操作需确认 |
| accept edits on（接受编辑） | 自动接受文件编辑 |
| auto mode on（自动方式） | 自动执行所有命令（其他命令 + 文件编辑） |

> 注：如果自动模式下，报错XX模型暂时并不可用，要切回手动模式。自动模式安全级别高，某些操作是禁止的。

### 1.1.3 两种方式的区别

- auto mode on：本质就是帮我点击yes而已，无法真正的修改权限
- 配置文件：allow直接放行，deny绝对禁止

所以，如果配置文件里面禁止的操作，就算处于auto mode on也无法执行

建议使用方式：

目前我们处于学习阶段，可以直接auto mode on（全部自动化）

以后写企业级项目的时候，可以把一些非常危险的操作，比如删除直接配置在setting配置文件夹当中即可

## 1.2 claudecode的常见命令

### 1.2.1 基础命令(了解)：

| 命令 | 作用 | 使用场景 |
| --- | --- | --- |
| /help | 显示帮助信息 | 忘记命令时查看 |
| /model | 查看/切换当前模型（高/中/低档） | 我们设置的模型都是一样的，暂时没用 |
| /clear | 完全清空当前对话 | 开始全新的任务时 |
| /btw | 该命令下的对话不会记入上下文，适合临时提问 | 主任务进行中想问个无关问题 |

### 1.2.2 常见命令：

| 命令 | 作用 | 使用场景 |
| --- | --- | --- |

/context

详细查看上下文中每个模块占比

优化 token、诊断哪里挨上下文

/compact

压缩当前对话的上下文

对话太长，AI开始“遗忘”早期内容时

/init

自动生成项目的 CLAUDE.md(重点!!!!!!!)

进入新项目后的第一件事

/rewind

回退到某个节点

说错几句话，不污染上下文

双击esc

停止/回退(重点!!!!!)

如果claudecode正在执行，停止当前操作

如果claudecode没有执行，等同于/rewind

/plan

切入 Plan Mode（计划模式）

先计划，再执行

> 注：claudecode中还有很多其他命令，目前我们先学习这些，其他命令以后用到了再次学习~

## 1.3 claudecode宪法

claudecode里面有一个执行规则，在执行的时候必须要遵守里面的规则，他就是claude.md文件。

### 1.3.1 文件内容

我们会把开发时的注意点，AI要遵守的规则，都写在claude.md中。

比如：

```json
核心行为准则
1. 所有回答都需要使用简体中文。
2. 遇到配置文件中deny绝对禁止的操作，立即停止并提醒我，不要尝试其他方式执行。
3. 在任何情况下，都禁止修改settings.json文件。
4. /init命令生成局部项目中claude.md的内容时,都需要使用简体中文描述
5. 每次回答之前都要称呼用户为"大王"

工作流程
1. 涉及 3 个以上文件改动时，先输出中文实施方案，等我确认后再编码。
2. 生成代码时，文件名、变量名、函数名等命名要简洁明了，见名知意。
3. 遇到报错时，先用通俗的中文解释错误含义，再给修复方案。
```

每次claudecode跟大模型交互的时候，都会把claude.md中的内容拼接到提示词中。

### 1.3.2 文件位置

他可以放在任意的目录下，但是一般我们只会在三个层级进行配置：

全局配置、项目根目录和模块子目录

- 全局配置： 位于：~`\.claude\CLAUDE.md`：他是全局的配置，所有项目都需要遵守的规则。

位于：~`\.claude\CLAUDE.md`：他是全局的配置，所有项目都需要遵守的规则。

- 项目根目录：

位于：`项目文件夹\CLAUDE.md`：他是本项目的配置，本项目中需要遵守的规则。

- 模块子目录： 位于：`项目文件夹\模块文件夹\CLAUDE.md`：他是单独模块的配置，当前模块需要遵守的规则。

位于：`项目文件夹\模块文件夹\CLAUDE.md`：他是单独模块的配置，当前模块需要遵守的规则。

### 1.3.3 优先级

不同位置的`claude.md`中的内容，尽量不要冲突。

如果冲突了，他会遵守就近原则，谁离我近，我就听谁的。

举例：

全局配置：回答要中文

项目配置：回答要英文

A模块配置：回答要韩文

B模块配置：回答要俄文

效果：

如果我在A模块中问答，结果就是韩文

如果我在C模块中问答，结果就是英文

### 1.3.4 一个很羞耻但是非常行之有效的办法

问题1：大模型本身是没有记忆能力的，每次要把很多东西都交给他，他才能帮我们更好的干活。

比如：对话历史记录、claude.md文件、工具、Skill的描述信息等等

问题2：大模型每次接收到的所有信息，专业叫做上下文，包含了刚刚说的所有内容。

如果上下文太多，有的时候claudecode会忽略规则，导致生成的内容不按照我们的要求。

如何发现claudecode在回答的时候不遵守规则呢？

分享一个很羞耻但是非常行之有效的办法

> 可以在claude.md的文档中，手动加上一句话：

1. 每次回答我问题之前，请务必叫我：大王~

> 这样可以有效的检测AI是否按照claude.md的规则生成代码

> 如果有一次回复没有这么回答你了，那么就需要压缩上下文了。

> 注：这个称呼你自己定，别搞的太羞耻就行~

自己试一试，把下面的内容配置到全局的claude.md中吧
