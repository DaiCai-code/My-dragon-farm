### 练习1：上班出行计划

课堂案例中，我们做过"上班出行计划"，但是该智能体功能不足。

比如：

用户出行默认是开车，我们也引入了高德地图的行驶骑车的插件，但是如果用户想问，"骑行，公交，开车哪种方式更快？"，智能体就无法满足了。

练习要求：

1. 用户想问"骑行，公交，开车哪种方式更快？"，智能体需要给出建议。
2. 每次问出行情况，默认对比哪种出行方式更快，并给出具体的理由。
3. 如果当前选择开车，假设用户车牌号码为：京A12345。要查询用户的车辆是否被限号。

出行方式排序规则如下：

- 如果遇到下雨，下雪，刮风等极端天气，建议开车，公交
- 如果车辆限号，建议公交，骑行
- 如果周末不上班，而且是晴天，建议骑行锻炼身体
- 时间最短，优先推荐
- 其他规则自行补充，合理即可

> 注1：北京早高峰堵车情况很严重，有的时候骑车、电驴比开车快。

> 注2：北京有车辆限号政策，该政策自行百度以知识库形式提交智能体。

> 注3：北京有的地区有公交车专用行车道，私家车不能进，所以有的情况下公交比开车更快。

```java
你好你是一个上班出行计划助手
你需要局部如下功能:
1. 通过插件完成当前时间的获取, 以及可以将时间转成其他插件想要的格式
2. 通过插件完成各种交通工具的出行时间耗时的查询
3. 通过查询知识库完成是否限号
4. 对比多种出行方案, 选择耗时最少的方案展示
5. 通过查询知识库,完成用户对应日期的上班班次
6.. 通过查询知识库, 完成用户的上班时间的获取
7. 通过工具查询指定日期的天气
约束:
1. 如果没有输入用户名, 默认用户是张三
2. 如果没有输入城市, 默认城市是郑州市
3. 如果没有输入目的地,, 默认是从二七广场到航投大厦
4. 需要结合各种交通工具的耗时, 选择耗时最短的出行方案,
如果下雨的话, 无视出行耗时, 直接摒弃骑行, 只能开车或者地铁

将以上的结果汇总给出暖心提醒的格式
```

### 练习2：校园百事通

完成业务： 校园百事通

一、 核心业务定位

现在你是清华大学的学生，现在要为学校打造一个能够7x24小时解答新生及在校生各类疑问的"校园百事通"，帮助学生快速适应校园生活

二、 本地知识库搭建

为了让你的AI客服具备"学校专属"的专业性，你需要整理并上传以下几类文档到Coze的知识库中：

> 备注：下面的这些内容课程资料没有准备，你如何操作呢？

1. 教务与考试指南：包含学校的选课规则、学分要求、期末考试安排、补考与重修政策、绩点计算方法等。
2. 校园生活手册：食堂开放时间、宿舍门禁制度、校园网连接教程、澡堂/体育馆开放时段、快递收发地址等。
3. 社团与活动大全：各大社团的介绍、招新时间、近期校园讲座预告、志愿者活动报名方式等。
4. 常见问题FAQ：整理历年新生最常问的50-100个问题（如"图书馆怎么预约座位？""学生证丢了怎么补办？"），制作成结构化的问答对。
- 练习建议：你可以将这些内容分别保存为PDF、Word或TXT文件，在Coze后台创建对应的知识库并上传。你还可以故意放一些错误信息，然后在调试阶段学习如何优化检索准确率。

三、 插件配置（拓展AI的能力边界）

单纯的问答可能略显枯燥，通过添加插件，可以让你的AI客服拥有"实时联网"和"实用工具"的能力：

1. 资讯获取类插件（如联网搜索、新闻插件）：让学生可以询问"今天有什么好玩的？"或者"学校当地有什么适合大学生玩的地方？。
2. 生活服务类插件（如地图/天气插件）：当学生问"明天去长城校区需要带伞吗？"时，AI能调用天气插件查询实时天气预报；或者调用地图插件，告诉学生从南门到图书馆的最佳步行路线。

四、 对话流与多轮交互设计

为了增加练习的深度，你可以设计引导学生多轮提问：

1. 明天去长城校区需要带伞吗？ AI回答完毕之后，引导继续提问。

AI回答完毕之后，引导继续提问。
